# Authoring Skills

This package is designed so that new skills can be generated by an AI and installed into Codex with a single command.

## Creation flow

```bash
# 1. Scaffold a new skill folder from skills/_template
node scripts/scaffold-skill.mjs my-skill

# 2. Open skills/my-skill/SKILL.md and ask an AI to fill it in.
#    The scaffold already substitutes the name so the AI only needs to
#    write description + body + (optional) hooks.

# 3. Validate the frontmatter and referenced scripts
node scripts/install-skills.mjs validate my-skill

# 4. Install to ~/.codex/skills
node scripts/install-skills.mjs install my-skill
```

## AI prompt template

```
I want a new Codex skill at `skills/<name>/SKILL.md`.

Requirements:
- Keep the existing frontmatter name; fill `description` with a concise one-liner used for skill discovery.
- Use the body to give step-by-step instructions the agent should follow when the skill triggers.
- If the skill needs hooks, add a `scripts/` subfolder and declare them under `hooks:` (allowed: session_start, stop, pre_tool_use, post_tool_use).
- Do not touch `.codex/` — it is auto-generated by the installer.

Goal: <describe what the skill should do>
```

## Minimum viable SKILL.md

```yaml
---
name: my-skill
description: Short one-line description.
---

# my-skill

## Overview
...

## Behavior
1. ...
```

`targets` defaults to `codex` when omitted.

## Common patterns

### Planning / workflow skills (like `autopilot`)
- Use `session_start` hook to prepare planning files.
- Use `stop` hook to enforce completion criteria (e.g. `autopilot`'s `scripts/check-completion.sh` keeps the agent running until every `plan.md` checkbox is `[x]`).

### Utility skills (like `webp`)
- Usually hookless; body just tells the agent which shell command to invoke.

### Codex-focused skills
- Leave `targets` unset unless you need to be explicit; the default is `codex`.
- Keep the body written for Codex's tool model and file-editing flow.

## After authoring

- `node scripts/install-skills.mjs validate` catches missing fields and dangling hook paths.
- `node scripts/install-skills.mjs install --dry-run` shows where symlinks will land without writing.
- `node scripts/install-skills.mjs status <name>` reports the current install state for Codex.
